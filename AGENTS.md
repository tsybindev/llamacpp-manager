## 🔄 Режим работы (Goal Execution Protocol)
Ты работаешь в полностью автономном режиме с ориентацией на конечный результат, следуя итеративному циклу:

### 1. Инициализация (Первый запуск)
Если репозиторий еще не создан или не настроен:
- Создай репозиторий через CLI `gh repo create` и привяжи его к текущей директории.
- Инициализируй Rust-проект (`cargo init`), установи все нужное, если отсутствует.
- Заполни файл `LOGS.md` для трекинга прогресса.

### 2. Планирование и Декомпозиция
- Изучи `PRD.md`. Разбей общую цель на мелкие, атомарные задачи и подзадачи.
- **Главный принцип:** Не делай большие задачи за один раз. Делай работу небольшими, логически завершенными частями (атомарные коммиты / функции).

### 3. Ведение журнала (`LOGS.md`)
После каждой выполненной задачи или подзадачи **обязательно** обновляй файл `LOGS.md`:
- Структурируй `LOGS.md` на: 
  - `[ ]` Предстоящие задачи (Backlog)
  - `[/]` В процессе (In Progress)
  - `[x]` Выполненные задачи (Completed) с датой/временем или описанием сделанного.

### 4. Итеративное выполнение (Execute -> Validate -> Log)
Для каждого шага:
1. Выбери самую маленькую невыполненную подзадачу из `LOGS.md`.
2. Напиши чистый, идиоматичный Rust-код.
3. Проверь компиляцию и тесты (`cargo check`, `cargo test`, `cargo clippy`).
4. Если есть ошибки — исправь их до перехода к следующему шагу.
5. Отметь подзадачу как выполненную в `LOGS.md`.
6. Делай коммиты локально по шагам, чтобы иметь возможность отката, запушим потом на GitHub.

## 🛠 Стандарты разработки и ограничения (Rust Guidelines)
1. **Production-Ready Code:** Никаких `todo!()`, `unimplemented!()` или `// TODO: реализовать позже` в основной логике. Код должен компилироваться и работать.
2. **Идиоматичный Rust:** Соблюдай лучшие практики (ownership, borrowing, обработка ошибок через `Result`/`Option`, без замалчивания `unwrap()` в продуктовом коде, где возможна паника).
3. **Безопасность типов:** Минимизируй использование `unsafe`, если это прямо не требуется по PRD для FFI/производительности.
4. **Маленькие шаги:** Если задача кажется большой (например, "написать gRPC сервер"), разбей ее: 
   - Шаг A: Добавить зависимости в Cargo.toml
   - Шаг B: Описать `.proto` схемы
   - Шаг C: Написать скелет обработчика
   - Шаг D: Покрыть юнит-тестом
